# Backlog v1.5-v1.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Finish the approved backlog so the Streamlit app can parse PDF/Word CVs, use stronger production-ready search configuration, provide city autocomplete, document deployment, and ship with versioning through v1.8.0.

**Architecture:** Keep parsing, search configuration, city lookup, and production readiness as focused modules. The Streamlit app remains a thin orchestration layer over tested package code, with private CV data kept outside Git and optional API keys read from environment or Streamlit secrets.

**Tech Stack:** Python 3.11+, Streamlit, SQLite, pypdf, python-docx, requests, BeautifulSoup, unittest.

**Spec:** `docs/PROJECT_SPEC.md`

## Global Constraints

- Keep actual CV files, extracted CV text, queue data, secrets, and `config/preferences.local.yaml` out of Git.
- Do not automate job-board login, CAPTCHA handling, or final application submission.
- Support `.pdf` and `.docx` CV text extraction; accept `.doc` uploads with best-effort legacy text extraction and clear user-facing limitations.
- Read optional search API keys from Streamlit secrets or environment variables, never from committed code.
- Use CountriesNow Malaysia cities with a local fallback list for production reliability.
- Update `README.md`, `CHANGELOG.md`, `docs/`, `pyproject.toml`, and `src/job_hunter/__init__.py` for each release stage through `1.8.0`.
